# Offering sweep — findings

Phase 2 of [extractor-rebuild-plan.md](extractor-rebuild-plan.md). Generated by `npm run sweep`
(Kambi only, no LLM). Per-sport fact sheets land in `.sweep/<sport>.json` (gitignored — they track the
live feed and go stale within days; this file is the durable read-out).

Method: for each built sport, read the sport-root event list, take the 12 busiest groups that actually
have events, and pull their menus. The sport-root menu alone is capped at 2000 offers, which badly
under-reports the dense sports — football reads as 265 market families from the root but **1227** once
its real groups are fetched.

Swept 2026-08-13: 41 built sports, 37 with live data.

## 2. The offering-type backbone

Every market family is one of 21 `betOfferType`s. This is the real vocabulary the extractor has to hit:

| type | offers | sports | notes |
|---|---|---|---|
| Over/Under | 11,143 | 23 | totals — the most universal type |
| **Player Occurrence Line** | 10,909 | **7** | all player props live here; huge volume, narrow spread |
| Handicap | 3,944 | 18 | + 3-Way Handicap (4), Asian Handicap (2) |
| Match | 3,439 | 22 | 1X2 / moneyline |
| Yes/No | 2,307 | 18 | binary props |
| Winner | 1,651 | 25 | outrights, awards, futures |
| Head to Head | 1,182 | 8 | |
| Position | 528 | 19 | finishing position / top-N |
| Correct Score | 385 | 8 | incl. tennis Set Betting, esports Correct Map Score |
| Double Chance | 364 | 5 | |
| **Winning Margin** | 325 | **5** | see §5 |

| HT/FT | 174 | 6 | |

| Player Occurrence Number / Scorer / Occurrence Method / Player Last Occurrence | <60 | 1–2 | long tail |

**Player props exist in only 7 sports**: american-football (45 families), basketball (55), z-sports (52),
baseball (39), australian-rules (26), football (15), esports (2). Corpus `player-prop` rows must come
from these — a player-prop query in cricket or tennis has to resolve through `Winner`-type markets
instead (`Top Run Scorer - St Lucia Kings`, `Most Aces`), which is a different shape.

## 3. Grain: where the outrights are

Competition-grain families (outrights, futures, awards), top of the list:

```

ice-hockey 16 · australian-rules 9 · snooker 9 · darts 8
```

American football is futures-heavy (`Series Result - Regular Season`, `To reach the Playoffs`,
`Team to win 35+ regular season games`); golf is almost entirely outright (2 fixture vs 102 competition).
These are the sports to lean on for `outright` coverage — the 58 probe queries barely touched this grain.

## 4. Event-name shape — the home/away inversion

A clean split, and it is the root cause of the Valkyries → Chicago Sky error:

| order | sports | example |
|---|---|---|
| `away @ home` | american-football, baseball, basketball, ice-hockey | `Detroit Lions @ Cincinnati Bengals` |
| `home - away` | everything else (football, tennis, rugby ×2, cricket, esports, MMA, darts, snooker, …) | `Penrith Panthers - Sydney Roosters` |

So in the four `@` sports, the team written **first** in the feed name is the **away** side — the
opposite of every other sport. Any rule that infers a side from position is wrong half the time, which
is why the extractor must keep the **named** subject and never substitute a positional guess.

## 5. Margin markets exist — we were missing them, not lacking them

The probes showed "Penrith by 13+", "Auckland by 15+" and "Australia by a big margin" all resolving to
the plain winner market and then dying on the line/odds gate. The feed carries the right markets:

```
rugby-league       11 families  "Win 9+ Margin - Regular Time", "Winning Margin 10pt - Regular Time"
australian-rules   14 families  "Margin 1-39 & 40+", "Margin 1-24 & 25+"
rugby-union         4 families  "Margin 1-12 & 13+ - Regular Time", "Winning Margin - Regular Time"
american-football   1 family    "Winning Margin Bands - Including Overtime"
basketball          1 family    "Winning Margin - Including Overtime"
```

`margin-market` is therefore a **resolvable** bug with a named target, not an absent offering.

## 7. What this changes for the corpus (Phase 4)

- **Player-prop rows** only from the 7 sports that carry `Player Occurrence Line`.
- **Outright rows** lean on american-football, golf, basketball, politics, motorsports.
- **Score-combo rows** from tennis (Set Betting, 16 families), football/ice-hockey (Correct Score), esports (Correct Map Score).
- **Margin rows** from rugby-league, australian-rules, rugby-union — with the real family names as `accept[]`.
- **Home/away rows** must include the four `@` sports, since that is where positional inference inverts.
- Sports with 1–2 families (chess, trotting, winter-sports, gaelic-sports, tv-novelty) can only support a
  smoke row — there is nothing else to ask for.
- The 4 dead sports and 74 missing groups are a **catalog** job (Phase 7), not a prompt job; corpus
  queries must avoid them or they will fail for the wrong reason.
