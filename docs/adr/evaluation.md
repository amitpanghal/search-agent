# ADR: Evaluation

Status: current
Last verified: 2026-09-30 against eb4aae8

## Purpose
Know whether a change to a prompt, the schema, a stage or a model made the resolver better or worse, before
it ships. The paid gate grades the model stages on a gold set; the free gates replay the deterministic
stages against captured data; the probe shows one query stage by stage.

## Input and output
- In: the gold decks, the captured menu snapshot, and (for a probe) a live run.
- Out: per-tag pass rates and a pass or fail exit code; a per-stage trace for one query.

## How it works
Paid, `npm run eval` (`src/eval/run.ts`), three independent gates in one run:
1. Extractor gate. Each gold query through the real `extract()` plus sport recovery, graded by text on the
   costly facets (sport, market wording, binding, line, odds). Rows are multi-tagged by the behavior they
   stress (37 tags): critical tags must pass 100%, soft tags 90% aggregate. Throttles are retried.
2. Entity gate, free inside the run. The real grounder on the gold's own entity text, graded on recall of
   the gold ids and on precision when the tier is clean.
3. Market-resolution gate. The market model picks from the captured snapshot menu by each gold concept
   phrase; pass means `exact` on a gold criterion id. Market type only.

Free:
- `npm test`: 41 deterministic invariants across the resolver and the log module, in about 2 seconds.
- `npm run gate:live-menu`: replays filter, select and execute against `live-menu.snapshot.json` with
  captured decisions. No network, no model.
- `npm run eval -- --from cap.jsonl`: re-scores extractions captured earlier by the probe. No model calls.
- `npm run typecheck`.

Gold decks: `gold.seed.jsonl` (12 hand-authored rows with real catalog and criterion ids; they drive the
entity and market gates) and `gold.corpus.jsonl` (279 generated rows, text-graded). The corpus is authored
compactly in `planning/corpus/gold-expect.jsonl` against `corpus.jsonl` and expanded by `npm run gold`;
never hand-edit the expanded file. `catalog-support.ts` excludes rows whose entities no catalog carries:
that measures catalog coverage, not extraction.

Probe: `npm run probe -- "query"` runs the live pipeline and prints one row per stage and per API call,
with tokens, cost and timing. `--until` stops before the next paid call; `--out` saves the full trace as
JSONL for reuse. The trace is no-op instrumentation: `emit()` fires only when a store is active.

## Key decisions and why
- **Grade the extractor by text, the market by id after the fetch.** The extractor's job is the wording;
  the criterion id only exists once the menu is known.
- **Deterministic gates are free and always run.** Model judgment is measured separately and rarely.
- **Catalog coverage is separated from extraction.** No prompt rewrite can win back a row the catalog
  cannot serve.
- **Replay from captures.** A gold or scorer fix re-scores the existing capture; only a prompt, schema or
  model change needs fresh extractions.
- **Paid runs need an OK first.** The default is one run per row; `--runs 3` for measuring a prompt delta;
  `--release` (5 runs) only for final sign-off.

## Invariants
- `npm run eval` exits non-zero on any critical miss.
- The trace never changes the shipped path: no store, no effect.

## Limits
- The snapshot is one fixture plus the World Cup 2026 outrights, captured 2026-06-22; the capture script it
  cites is no longer in the repo, so the snapshot cannot be regenerated by the documented path.
- `gold.meta.json` row counts are stale (it says 14 and 289; the files hold 12 and 279).
- No test covers the HTTP route; `plan-recall` has no test of its own.
